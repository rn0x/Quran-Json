# Quran Data v3.1.0

## Data pipeline verification
Tested against the project's real `data` directory:

- 114 surahs
- 6,236 verses
- 18,012 surah-audio rows
- 158 reciter IDs
- 96 timing reciters
- 600,327 ayah timing rows
- 38 ayah-by-ayah audio reciters
- 6,582 JSON files under `data/json`
- CSV: 114 data rows + header

### Important fixes
- `jsonToSqlite.mjs`: audio primary key is now `(id, surah_number)`. The old schema collapsed 18,012 rows into only 158 rows.
- `jsonToCsv.mjs`: no longer depends on the missing `json2csv` package.
- `addTimingToSqlite.mjs`: imports all 600,327 source rows. Four source rows have `end_time < start_time`; they are preserved as-is and reported as source anomalies.
- `addJsonToSqlite.mjs`: upserts by `file_path`, not only `file_name`, and supports `--file` / `--folder`.
- Added `verify:data` and `data:rebuild` scripts.

## Vercel
`vercel.json` now uses `functions` + `rewrites` instead of legacy `builds` + `routes`.

The project currently needs the Large Functions beta because the deployed function is above 250 MB. `VERCEL_SUPPORT_LARGE_FUNCTIONS=1` must be enabled for the environment being deployed. A Git branch deployment is a **Preview** deployment, so a variable scoped only to **Production** will not apply to it.
